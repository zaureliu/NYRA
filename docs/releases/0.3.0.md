# NYRA 0.3.0 — Self-Development Engine V1

Esta release acrescenta um ciclo local e reversível de melhoria de software. Evidência recorrente ou solicitação explícita entra em uma fila persistente; um plano estruturado classifica risco, cria candidato isolado, aplica patch tipado, executa validações e só então permite promoção por commit.

## Segurança e privacidade

- Nenhuma resposta textual do LLM é executada como comando.
- Git, testes e builds passam por `system_shell`; approvals continuam vinculados e de uso único.
- HIGH_RISK não é autopromovido. Credenciais, approval, redaction, shell, host keys, segurança e publicação são áreas protegidas.
- O modelo padrão é o Ollama local `qwen3:8b`; downloads e cloud não são acionados pelo motor.
- Auto Publish fica OFF no bootstrap. Publicação usa somente o snapshot definido por `NYRA_SELFDEV_PUBLIC_SNAPSHOT`, após scan sanitizado sem achados.
- Estado mutável fica fora do Git em `%LOCALAPPDATA%\NYRA`.
- A API local valida Host/Origin inclusive no WebSocket; áudio transcrito não é um canal de approval.
- Jobs/processos arbitrários não ficam expostos ao LLM, tarefas/workflows ou REST, e scripts de navegador exigem approval ligado à aba, URL completa e script exato.
- Homelab é somente leitura por padrão; SSH usa `known_hosts` estrito e credenciais remotas exigem HTTPS ou loopback literal.
- Avaliação aninhada de shell nunca é tratada como read-only; remediação SSH automática exige correspondência integral do comando.
- Credenciais Home Assistant/Proxmox são invalidadas quando a origem muda. O Sentinel aceita host manual apenas como IP local literal e exige HTTPS fora de loopback.

## Operação

O painel está em `Configurações > Self-Dev`. Modos disponíveis: OFF, OBSERVE_ONLY, AUTONOMOUS_SAFE e AUTONOMOUS_ADVANCED. Consulte [Self-Development Engine V1](../self-development.md) para configuração, API e recuperação.
