# NYRA 0.5.0 — Runtime and Autonomy Upgrade

This release updates the public source snapshot while preserving local-first,
modular execution and evidence-based results. The project remains **NYRA**.

## Runtime and voice

- Deepgram Nova-3 STT supports streaming, interim/final separation and fallback
  to Faster-Whisper. The existing microphone/VAD pipeline remains the owner.
- Natural Conversation keeps sessions open across turns and tools. Turn detection,
  barge-in, cancellation, echo protection, LLM segmentation and Speech Planner
  share the existing orchestration, persona, emotion and speech queue.
- Universal TTS includes Local/Kokoro, OpenAI, ElevenLabs, native Gradium and
  declarative Custom REST/WebSocket providers. Capabilities and actual provider
  configuration determine streaming and acoustic behavior.
- Voice settings readability and shutdown coordination have been improved.

## Research and autonomy

- Web Research uses real sources, official-document ranking, bounded refinement,
  verified HTTPS, provenance and DuckDuckGo/Bing fallback. The runtime hotfix
  decodes compressed content and retains actionable provider/fetch diagnostics.
- Natural version/documentation questions reach the registered Web tools. A
  failed search provider does not establish that the machine is offline.
- Hardware Engineering supports discovered USB/serial devices, technical profiles,
  project continuation, general code changes, dynamic replanning, bounded build
  repair and adapter-based flash/serial verification.
- World State, Open Loops/Goal Memory, Artifact Context, Tasks, Proactive Presence
  and Persona/Emotional Runtime remain shared authorities, not duplicate engines.
- Network Observability V2 and VTube Studio-only presence/mouse tracking are included.

## Privacy and distribution

Only source, public templates, tests and documentation are published. No operator
knowledge corpus, PDFs, RAG index, generated hardware workspace, audio recording,
runtime database, credentials, private topology or third-party VTube model is
included. Unfinished model-specific VTS changes are excluded.

Credentials are stored through Credential Broker. Cloud providers are optional,
require operator configuration and may incur provider charges. Local inference
requires locally provisioned models; an absent optional provider is not a startup
failure and is never presented as configured.

The release follows the previous source-only GitHub distribution format: no
installer, portable ZIP, model pack or voice asset is attached. Local PyInstaller
and Tauri outputs are validation artifacts, not source-tree contents.

## Reproducible Windows build

Use Windows 10/11, Python 3.11, Node/npm, Rust and the Tauri build prerequisites.
From a clean clone:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-release-windows.lock
npm.cmd --prefix frontend ci
npm.cmd --prefix desktop ci
# Choose a fresh local runtime folder outside the source tree.
$env:NYRA_DATA_HOME = Join-Path $env:LOCALAPPDATA 'NYRA-Release-Validation'
powershell -ExecutionPolicy Bypass -File scripts/download_tts_models.ps1
npm.cmd run build:release
```

Python dependencies are pinned for Windows/Python 3.11; npm and Cargo lockfiles
are included. Public TTS model downloads are explicit and SHA-256 checked by the
provided script; they are not copied from an operator workspace. Dependencies
may require Internet during initial provisioning. Runtime locations are derived
from the clone, the user profile or `NYRA_DATA_HOME`, not a developer drive.
Generated hardware workspaces use `NYRA_PROJECTS_ROOT` when set, otherwise
`<USER_HOME>/NYRA-Projects`.

## Validation and limitations

Release-candidate validation on Windows / Python 3.11:

- Public source: 350 targeted backend tests, 147 frontend tests and 24 Rust
  library tests passed. Frontend TypeScript/Vite build passed; no separate
  frontend lint script is configured.
- A separate clean validation clone installed the pinned Python, npm and Cargo
  dependencies. All 147 frontend tests and 13 final backend configuration,
  packaging and release-contract checks passed there.
- Both the public checkout and the clean environment produced a PyInstaller
  backend and Tauri release executable without operator workspaces or VTS assets.
- The clean packaged backend reported version 0.5.0 and local STT/TTS fallbacks.
  A no-cloud-key startup used the existing process-scoped Broker-disable setting
  to avoid accessing the operator's Windows cloud credentials. Cloud voice
  credentials were unavailable in that process; the operator vault was untouched.
- Real packaged Web Research retrieved the specific official `pio run` document
  over certificate-validated HTTPS. DuckDuckGo returned HTTP 202; Bing RSS
  fallback returned real results and retained source provenance.
- The owned-backend shutdown command was reached and the isolated port was freed.
  Headless Windows SIGINT can reset its HTTP response; no graphical tray or
  complete UI/audio shutdown validation is claimed by this source-release smoke.
- The bounded source secret/privacy gate found no real secrets or forbidden
  runtime assets. Local documentation links and Git whitespace checks passed.

Cloud voice tests without credentials and physical hardware tests without devices
are not claimed as real passes. VTube facial capabilities depend on the external
model. This is targeted release validation, not a claim that every integration or
the entire historical test suite was exercised.

The historical Web outage was not reproduced for the exact PlatformIO prompts;
the hotfix addresses independently reproduced extraction, routing and diagnostic
defects. DuckDuckGo HTTP 202 remains an upstream limitation, with real Bing/direct
HTTPS fallback. No TLS bypass was introduced.

Synthetic credentials, RFC1918 network addresses and an `Operator` path in tests
exercise redaction and private-network policies; they are fixtures, not operator
configuration. These do not grant access to a real host or account.
